## 直接答案 {#answer}

对象存储容量已经很便宜，而且两家价格相当接近。真正拉开账单的是其他部分：

\[
\begin{aligned}
\text{对象存储月成本} ={}& \text{计费容量} + \text{请求} \\
&+ \text{取回} + \text{最短时长违约} \\
&+ \text{复制} + \text{公网/跨地域传输} \\
&+ \text{管理功能}
\end{aligned}
\]

自建的分母也不是裸盘 TB：

\[
\begin{aligned}
\text{原始需求} ={}& \text{逻辑数据} \times \text{纠删码/副本开销} \\
&\times \text{空闲水位} \times \text{站点份数} \\
&+ \text{备盘} + \text{复制网络}
\end{aligned}
\]

所以对象存储不存在一个统一的“下云规模”；第一问永远是最小可靠拓扑是什么。

| 存储类别 | AWS `us-east-1` | 折算人民币 | 阿里 OSS LRS |
| --- | ---: | ---: | ---: |
| 标准 | `$0.023/GB月` | `¥0.156` | `¥0.120` |
| 低频 | `$0.0125` | `¥0.0848` | `¥0.080` |
| Glacier Instant / 归档 | `$0.004` | `¥0.0271` | `¥0.033` |
| Glacier Flexible / 冷归档 | `$0.0036` | `¥0.0244` | `¥0.015` |
| Deep Archive / 深度冷归档 | `$0.00099` | `¥0.0067` | `¥0.0075` |

这些行只是价格相邻，不代表服务等价。取回延迟、可用性、耐久拓扑、恢复流程和功能语义都不同。

## 小对象税 {#small-objects}

冷存储通常按最小对象大小计费：

| 服务类别 | 最小计费对象 | 最短存储期 | 额外元数据 |
| --- | ---: | ---: | ---: |
| S3 Standard-IA / One Zone-IA | `128 KB` | `30 天` | — |
| S3 Glacier Instant | `128 KB` | `90 天` | — |
| S3 Glacier Flexible / Deep Archive | 对象字节 | `90 / 180 天` | `40 KB/对象` |
| OSS 低频 / 归档 / 冷 / 深冷 | `64 KB` | `30 / 60 / 180 / 180 天` | 依产品而定 |

1 KB 对象在账单上可能膨胀 128 倍或 64 倍；10 KB 对象也会膨胀 12.8 倍或 6.4 倍。
进冷存储前要统计对象数量分布、平均与分位大小、覆盖/删除率和保留期，而不是只看总 TB。

## 活动型计量项 {#activity}

### 请求 {#requests}

快照参考价：

- S3 Standard PUT/COPY/POST/LIST：`$0.005 / 千次`。
- S3 Standard GET：`$0.0004 / 千次`。
- OSS Standard：每地域每月前 500 万 PUT、2000 万 GET 免费，超出后 `¥0.01 / 万次`；
  低频/归档 PUT/GET 常见 `¥0.10 / 万次`。
- OSS 深度冷归档 PUT：`¥3.50 / 万次`。

请求政策变化很快；甚至在控制台浏览也会产生 GET/LIST。对象数很高时，容量很小也可能产生明显费用。

### 取回与提前删除 {#retrieval}

快照示例：

- S3 Standard-IA 取回 `$0.01/GB`，Glacier Instant `$0.03/GB`。
- OSS 低频 `¥0.0325/GB`，归档 `¥0.06/GB`，冷归档标准取回 `¥0.06/GB`，深冷标准 `¥0.018/GB`。

最短期限前删除、覆盖或转层，可能收取剩余时长费用；归档恢复还可能创建一份按热存储收费的临时副本。

### 传输：交付费，也是退出费 {#transfer}

| 路径 | 快照价格 |
| --- | ---: |
| AWS 聚合公网出流 | 前 100 GB 免费；后续 10 TB `$0.09/GB`（`¥0.610/GB`） |
| AWS 同地域跨 AZ | 常见每方向 `$0.01/GB` |
| 阿里杭州 ECS 公网出流 | `¥0.80/GB` |
| 阿里 OSS 忙时 / 闲时公网出流 | `¥0.50 / ¥0.25 每 GB` |
| 阿里 OSS 到 CDN 回源 | `¥0.15/GB` |

同一份下载从 ECS、OSS 忙时、OSS 闲时或 CDN 出口，价格完全不同。先画完整数据路径，再报价。
对于退出，还要核查减免资格与操作提前期；有条件申请的减免不等于默认零费率。

## 资源包与承诺风险 {#packages}

阿里 OSS Standard LRS 100 GB 展示了资源包阶梯：

| 购买方式 | 总价 / 月等价 | 相对按量 |
| --- | ---: | ---: |
| 按量容量 | `¥12/月` | `100%` |
| 月包 | `¥11/月` | `91.7%` |
| 半年包 | `¥54.78` | 月等价约 `76.1%` |
| 一年包 | `¥99` | 月等价 `68.8%` |

未用容量到期作废，地域、冗余类型和计费项不匹配也可能无法抵扣。
资源包只有在范围与真实用量匹配时才降低有效单位价。

## 自建从拓扑开始 {#topology}

已发布情景使用 75% 纠删码效率、80% 最大安全填充、5% 备盘库存、5% 月数据变更率，
远程复制每 100 TB/月配一个实际可用的 1 Gbps 端口。

| 拓扑 | 最小节点 / 站点 | 能代表什么 |
| --- | ---: | --- |
| 四节点下界 | 4 / 单站 | 历史容量下界，不是当前完整生产基线 |
| 八节点单站 | 8 / 单站 | 当前生产 host 下界，节点/磁盘故障域 |
| 八节点双站 | 16 / 两站 | 异地完整副本，加复制网络 |
| 八节点三站 | 24 / 三站 | 保守多故障域近似 |
| Backblaze 类 Vault | 20 / 20 机柜 | 17+3 纠删码，跨机柜故障域 |

没有一种拓扑天然等价于 S3 Standard 的服务等级。耐久性、可用性、API 语义、运维、审计与恢复要单独测试。

增加站点会复制硬件，并叠加复制网络，答案随之改变。

## 第一次容量交点与稳定交点 {#crossings}

| 自建拓扑 | AWS S3 Standard 目录价 | 阿里 OSS 按量 | 阿里 OSS 一年包 |
| --- | ---: | ---: | ---: |
| 四节点单站下界 | `55 TB` | `71 TB` | `95 TB` |
| 八节点单站生产基线 | `115 TB` | `149 TB` | `199 TB` |
| 八节点双站 | `310 TB` | `402 TB` | `536 TB` |
| 八节点三站，第一次 / 稳定 | `498 / 498 TB` | `647 / 647 TB` | `863 / 1,223 TB` |
| 20 节点 / 20 机柜 Vault | `642 TB` | `834 TB` | `1,112 TB` |

这些只是 **容量 + 复制网络的物料交点**。云侧没有加入 S3/OSS 请求、取回和小对象开销；
自建侧没有加入商业软件、支持、负载均衡、安全和内部人力。

### 对 OSS 一年包的敏感性 {#sensitivity}

| 变化 | 八节点单站 | 双站 | 三站稳定交点 |
| --- | ---: | ---: | ---: |
| 基准 | `199 TB` | `536 TB` | `1,223 TB` |
| 硬件 -25% | `169 TB` | `476 TB` | `1,047 TB` |
| 硬件 +25% | `229 TB` | `597 TB` | `1,399 TB` |
| 安全填充 60% | `199 TB` | `536 TB` | `2,363 TB` |
| 月变更率 20% | `199 TB` | `1,047 TB` | `7,665 TB` |
| 高机房价 | `224 TB` | `587 TB` | `1,300 TB` |

单站容量对写入 churn 不敏感，多站对象存储则极其敏感。
高频改写数据可能更适合数据库、块存储或共享文件系统，而不是让所有对象副本持续跨站复制。

## 历史洞见 {#history}

S3 Standard 从 2006 年 `$0.15/GB月` 降到 2016 年 `$0.023`，此后到快照日保持不变。
阿里 OSS Standard 目录价在 2018 年到 `¥0.12`，2024 年出现长期公开有效价 `¥0.09`。
容量在早期像硬件一样快速下降，随后变成平台计量项；出网和活动费没有沿用同一曲线。
参见[云价历史](/zh/ledger/price-history/)。

## 决策区间 {#decision}

| 工作负载 | 基准倾向 |
| --- | --- |
| `<100–200 TB`、增长未知 | 云对象存储消除最小资源池成本 |
| `约 0.2 PB+`、单站容量 | 八节点自有容量进入经济区间 |
| `约 0.5 PB+`、双站副本 | 值得做正式自建对比 |
| `约 0.9–1.3 PB+`、三站/机柜故障域 | 可靠拓扑自建可能跨过正常云容量价 |
| 稳定交付 `20–25 TB/月+` | 固定带宽/CDN 与按 GB 出网要单独比较 |
| 全球边缘、DDoS、波动需求 | 即使源站自建，也继续购买 CDN 与弹性边缘 |

下云不等于拒绝 CDN、边缘或托管安全。常见高效组合是持有稳定源站容量，继续购买具有统计复用优势的分发服务。

## 边界 {#boundaries}

- 容量交点不是 SLA 或耐久性认证。
- 四节点 MinIO 只作为下界保留。
- 基准不计商业对象存储软件与内部运维。
- DHH S3 观察值使用 billed footprint；改用 primary logical data 会得到不同分母。
- 请求政策、资源包和价格可能在 2026-08-22 后改变。
