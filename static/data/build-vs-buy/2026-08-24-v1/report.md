# 买云，还是买机器？

## 自建 EC2、RDS、S3 的规模经济与成本拐点

AWS 与阿里云价格体系第二研究报告

受众：CTO、基础设施负责人、数据库负责人、FinOps 与采购团队

研究日期：2026-08-24

云价快照：2026-08-22

> 本报告回答一个具体问题：在不计企业内部人力、只计硬件、机柜、功率、电力、网络设备、基础线路、备件、折旧与资金成本时，自建 EC2、RDS PostgreSQL 和 S3 类服务的单位成本如何随规模变化，以及相对 AWS 和阿里云分别在何处出现经济拐点。

## 执行摘要

### 直接答案

**不存在一个统一的“下云规模”。EC2、RDS 和 S3 有三条完全不同的成本曲线。**

本报告在中国企业级 IDC 基准下，使用 5 年直线摊销、70% 目标装箱率、当前企业服务器与 IDC 公开报价，并对照 2026-08-22 AWS us-east-1 与阿里云杭州价格快照，得到以下基准交点：

| 服务 | 自建基准 | 对照云价 | 第一次低于云 | 稳定低于云 |
|---|---|---:|---:|---:|
| EC2 类 x86 算力 | 192 vCPU Dell 级服务器 | AWS c7a 按量 | 14 vCPU | 14 vCPU |
| EC2 类 x86 算力 | 同上 | AWS 3 年 Standard RI 代理 | 36 vCPU | 36 vCPU |
| ECS 类 x86 算力 | 同上 | 阿里 c8i 按量 | 24 vCPU | 24 vCPU |
| ECS 类 x86 算力 | 同上 | 阿里 c8i 5 年公开期限价 | 121 vCPU | 2,972 vCPU |
| RDS PG 高可用 | 两台 96 vCPU / 512 GiB / 9.6 TB NVMe | AWS RDS 1 年全预付 RI | 11 业务 vCPU | 11 业务 vCPU |
| RDS PG 高可用 | 同上 | 阿里 RDS 3 年全预付 Savings Plan | 34 业务 vCPU | 34 业务 vCPU |
| S3 类单站点 | 8 节点、EC:4、80% 填充 | AWS S3 Standard | 115 TB | 115 TB |
| S3 类单站点 | 同上 | 阿里 OSS Standard 1 年包 | 199 TB | 199 TB |
| S3 类双站点 | 每站 8 节点，5% 月变更率 | AWS S3 Standard | 310 TB | 310 TB |
| S3 类双站点 | 同上 | 阿里 OSS Standard 1 年包 | 536 TB | 536 TB |
| S3 类三站点 | 每站 8 节点，5% 月变更率 | 阿里 OSS Standard 1 年包 | 863 TB | 1,223 TB |
| Backblaze 类 Vault | 20 节点、20 机柜、17+3 EC | 阿里 OSS Standard 1 年包 | 1,112 TB | 1,112 TB |

“第一次低于云”表示某一个装箱区间开始便宜；“稳定低于云”表示之后即使再购买服务器、机柜或存储池发生跳阶，也不再反转。两者差距越大，说明成本曲线的整数阶梯效应越强。

### 五个最重要的判断

1. **EC2 的真正拐点不是机柜，而是一台服务器能否被持续填满。** 对按量云价，自建在十几到几十个稳定 vCPU 就能回本；对阿里 5 年深折扣，自建必须把硬件用得足够满，并跨过多轮扩容跳阶，稳定优势才出现。
2. **RDS 的拐点远早于 EC2。** 原因不是自建数据库的软件免费，而是 RDS 对两份计算、逻辑存储和管理能力按产品费率收费。即使对照阿里 3 年全预付，64 GiB/业务 vCPU 基准也在约 34 业务 vCPU 达到稳定交点。
3. **S3 的拐点由可靠性拓扑决定，而不是硬盘单价决定。** 单站点容量在约 0.1-0.2 PB 进入优势区；双站点约 0.3-0.6 PB；三站点或 20 机柜 Vault 约 0.6-1.3 PB。把四台 MinIO 服务器直接称为 S3 等价会严重低估成本。
4. **绝大多数规模经济发生在最开始。** EC2 类自建从一台服务器充分装箱到几十个机柜，单位物料成本只再下降约 15%-25%；RDS 大规模平台也主要从备机、机柜和网络共享中获得增益。机房规模不是魔法折扣。
5. **带宽有自己的拐点。** 以公开 1 Gbps 线路 12,500 元/月、实际承载 100 TB/月计，专线在月出流约 20.5 TB 时低于 AWS 0.09 美元/GB，在 25 TB 时低于阿里 OSS 忙时 0.5 元/GB。小流量继续按量更好，大流量买端口更好。

### 一句话结论

> 稳定负载先出现 EC2 拐点，数据库因托管溢价更高更早出现 RDS 拐点，而对象存储必须等到最小可靠性拓扑被摊薄后才出现 S3 拐点。真正的决策变量是稳定利用率、故障域和流量，而不是公司人数或“几台机器”这种模糊规模。

## 1. 问题边界与比较原则

### 1.1 本报告计入什么

基础物料成本包括：

- 服务器、CPU、内存、NVMe SSD、HDD、网卡和电源。
- 机柜、功率、电力、制冷、PDU、基础机房服务。
- 交换机、基础上联、必要的跨站点复制线路。
- 备件库存、冗余节点、容量安全水位。
- 3-7 年折旧情景，基准 5 年。
- 8% 资金成本下的等额年金经济成本，作为直线摊销的校验。
- 云上的计算、存储和与场景相关的公网流量。

### 1.2 本报告明确不计什么

用户要求先不考虑人力，因此以下项目不进入基准交点：

- 内部运维、DBA、SRE、网络与安全人员工资。
- 迁移项目人力、培训和组织变更成本。
- 应用改造、停机风险和机会成本。
- 自研控制面的软件研发成本。
- 商业 MinIO AIStor、VMware 或其他专有软件授权。

供应商硬件保修、远程 hands、机房白手套服务若已经包含在公开报价中，仍保留在物料路径里。它们是外采服务，不是内部人员成本。

### 1.3 不建立自己的数据中心

本报告中的“一个机房”是租用专业 IDC 的机柜、专区或机房房间，不是从土地、变电站、柴油机、UPS、冷站和消防开始建设数据中心。37signals 也明确说明，除超大规模企业外，拥有服务器通常意味着租用 Equinix、Deft 一类专业机房，而不是自己盖楼。[The Big Cloud Exit FAQ](https://world.hey.com/dhh/the-big-cloud-exit-faq-20274010)

如果企业要自行建设物理数据中心，供配电与制冷基础设施资本开支必须另外建模。2009 年 Microsoft Research 的 50,000 台服务器模型中，服务器约占摊销成本 45%，供配电与制冷基础设施约 25%，电费约 15%，网络约 15%。这不是 2026 年报价，却说明遗漏设施资本会造成数量级错误。[The Cost of a Cloud](https://www.microsoft.com/en-us/research/wp-content/uploads/2009/01/p68-v39n1o-greenberg.pdf)

### 1.4 容量等价不等于服务等价

本报告始终区分三层比较：

| 比较层 | 定义 | 典型用途 |
|---|---|---|
| 资源等价 | 相同 vCPU、内存、裸容量 | 判断纯租售比 |
| 拓扑等价 | 相同节点数、副本数、备机和故障域 | 判断高可用物料成本 |
| 服务等级等价 | 再加入 SLA、跨 AZ、恢复和控制面能力 | 判断产品替代关系 |

AWS S3 Standard 会把对象冗余保存在至少三个 Availability Zone，并设计为 11 个 9 的持久性。[AWS S3 Data Protection](https://docs.aws.amazon.com/AmazonS3/latest/userguide/DataDurability.html) 一个单站点 MinIO 集群只能用于容量或节点故障等价，不能被描述为完整 S3 Standard 等价。

## 2. 为什么规模曲线是锯齿，不是直线

### 2.1 固定成本、阶梯成本与线性成本

自建成本可以写成：

`Monthly = HardwareAnnuity + ColoStep + FabricStep + BaseTransitStep + ReplicationTransit`

其中：

- 服务器与磁盘在一个采购批次内近似线性。
- 一台服务器、一个备机、一个机柜、一个 1 Gbps 端口都是整数阶梯。
- 机柜按 U 和功率两个约束中更紧的一个装箱。
- 存储池要按 erasure set 或 server pool 成组扩容。
- 跨站点流量随数据变更率近似线性，但端口采购仍是阶梯。

所以单位成本不是连续下降，而是：装箱时下降，扩容瞬间上跳，再继续下降。

### 2.2 第一次交点与稳定交点

假设一台服务器在 70% 目标装箱率下能承载 134 个业务 vCPU。负载从 14 增加到 128 vCPU 时，固定成本被不断摊薄；负载超过 134 vCPU 后需要新增两台机器，其中一台承担 N+1 备机，单位成本会突然上跳。

因此本报告报告两个交点：

- **第一次交点：** 当前装箱区间中首次低于云。
- **稳定交点：** 此后所有扩容阶梯都低于云。

对高价按量云，两者通常相同。对阿里五年深度预付这种接近硬件摊销价的产品，两者可能相差一个数量级。

### 2.3 云为什么能消除用户的锯齿

Berkeley 的经典研究指出，公有云通过海量租户的统计复用，将客户的过度采购和不足采购风险聚合起来，并把资源变成按量服务。[Above the Clouds](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2009/EECS-2009-28.html)

用户支付的弹性溢价，本质上是把自己的锯齿交给云厂商。负载短、波动大或企业可能很快失败时，这个保险有价值；负载长期稳定时，云厂商把同一批硬件反复出租，用户持续支付租金，租售比开始主导。

## 4. 统一财务与容量模型

### 4.1 直线摊销与经济年金

基准现金摊销为：

`HardwareCashMonthly = Acquisition / 60`

经济成本使用 8% 年资金成本：

`HardwareEconomicMonthly = Acquisition x monthly_rate / (1 - (1 + monthly_rate)^-60)`

同一方法也用于校正云上的全预付。这样不会一边把服务器采购当免费资金，一边把云预付款当简单月均，或反过来。

### 4.2 体量折扣不是事实，而是输入

模型使用 1-4 台无折扣、5-19 台 2%、20-99 台 5%、100-999 台 10%、1,000 台以上 15% 的采购折扣，仅用于敏感性。没有任何厂商存在通用公开的服务器批量折扣表。

DHH 的真实成交、Dell 起价和浪潮市场报价能够证明议价存在，但无法证明每个客户都能拿到同一折扣。工作簿允许把这张表全部改为 0。

### 4.3 业务单位

| 服务 | 业务单位 | 关键容量约束 |
|---|---|---|
| EC2/ECS | 稳定占用 vCPU/月 | CPU、内存、目标利用率、N+1 |
| RDS | primary 业务 vCPU/月 | 主备两份计算、两份数据、备份 |
| S3/OSS | 逻辑 GB/月 | EC、填充率、站点副本、变更率 |
| 流量 | 出方向 GB/月 | 端口容量、利用率、云按量单价 |

对象存储沿用硬盘与云对象存储的十进制 GB/TB；内存与数据库块容量使用 GiB。18 TB 硬盘不被误写成 18 TiB。

## 5. 自建 EC2/ECS 的规模成本

### 5.1 基准架构

计算池使用 DHH 类服务器：192 vCPU、384 GiB、19.2 TB fleet-average NVMe、2U、约 16.95 万元。业务目标装箱率 70%。从第二台 active server 开始，至少保留一台备机；大规模时备机比例约 5%。

这比只算 CPU 更保守，因为服务器价格里包含本地 NVMe，而 AWS c7a 与阿里 c8i 的云价不含 EBS/ESSD。

### 5.2 单位成本如何随规模变化

| 稳定业务 vCPU | 服务器总数 | 机柜 | 现金成本 ¥/vCPU月 | 8% 经济成本 ¥/vCPU月 |
|---:|---:|---:|---:|---:|
| 16 | 1 | 0 | 220.36 | 258.61 |
| 32 | 1 | 0 | 110.18 | 129.30 |
| 64 | 1 | 0 | 55.09 | 64.65 |
| 128 | 1 | 0 | 27.54 | 32.33 |
| 192 | 3 | 0 | 55.09 | 64.65 |
| 512 | 5 | 1 | 40.15 | 46.00 |
| 1,000 | 9 | 1 | 31.63 | 37.03 |
| 4,000 | 32 | 4 | 27.56 | 32.21 |
| 16,000 | 126 | 13 | 23.21 | 27.55 |
| 64,000 | 501 | 51 | 22.89 | 27.20 |

曲线展示了两个规律：

- 第一台服务器从 16 到 128 vCPU 被填满时，单位成本下降 8 倍。
- 从 4,000 到 64,000 vCPU，规模扩大 16 倍，单位成本只再下降约 17%。

这就是“规模经济前置”。决定小企业是否适合自建的是能否填满第一批服务器；决定大企业成本的是利用率和硬件寿命，而不是再多买几十个机柜。

### 5.4 为什么阿里五年价是特殊对手

阿里 c8i 5 年公开价格约 29.35 元/vCPU月，与一台高装箱率自建服务器的直线摊销非常接近。此时：

- 自建在单机接近满载的 121-134 vCPU 区间先获胜。
- 新增 active server 和备机后单位价反转。
- 到约 2,972 稳定 vCPU 后，规模摊薄所有后续阶梯。
- 计入 8% 资金成本后，云五年全预付的经济单位价升至约 35.71 元，自建稳定交点反而提前到约 1,627 vCPU。

五年预付和买服务器具有相似的资金锁定，但服务器期末仍有残值与本地 NVMe，云承诺只有使用权。反之，云承诺不需要处理硬件故障、扩容交货期与资产处置。

### 5.5 EC2 的决策区间

| 稳定负载 | 基准判断 |
|---|---|
| 少于 16 vCPU | 按量云通常优先；服务器固定成本未摊薄 |
| 16-64 vCPU | 相对 AWS 和阿里按量，自建开始有物料优势；相对长期承诺未必 |
| 64-134 vCPU | 单台企业服务器的高性价比甜点区 |
| 134-600 vCPU | 扩容锯齿明显，需按实际机型和备机重算 |
| 约 600-3,000 vCPU | 对 1-3 年云承诺自建稳定占优；对阿里 5 年价取决于装箱率 |
| 数千 vCPU 以上 | 在基准 5 年寿命与 70% 利用率下，自建物料成本稳定低于所有对照云价 |

## 6. 自建 RDS PostgreSQL 的规模成本

### 6.1 为什么 RDS 必须按业务 vCPU 比

高可用 PostgreSQL 的一份业务算力需要：

- primary 一份计算与本地数据。
- standby 一份计算与本地数据。
- 至少一份远程备份。

本报告的业务 vCPU 指 primary 可服务的 vCPU。两台物理机的 128 vCPU 不是 128 业务 vCPU，而是约 64 业务 vCPU 的主备拓扑。

AWS 经典 RDS Multi-AZ 同样是 primary + standby；阿里高可用系列也是一主一备。第一份报告已经对云上节点语义做过核对，本报告沿用相同拓扑，不拿单机自建与双节点 RDS 比。

| 逻辑 GiB/业务 vCPU | AWS 1年 RI 稳定交点 | 阿里 3年 SP 稳定交点 |
|---:|---:|---:|
| 20 | 12 vCPU | 40 vCPU |

1,000 GiB 情景的阿里稳定交点反而升高，不是云存储突然便宜，而是自建节点的本地盘容量成为约束，每次扩容都会产生更大的锯齿。第一次交点仍只有 3 vCPU。这说明对超大盘数据库必须查看完整离散曲线，不能只看单个交点。

### 6.6 专机 RDS 与池化 RDS

本报告主模型是池化 RDS：不同 PostgreSQL 集群可以共享物理服务器池，但每个集群仍有主备逻辑资源。

如果每个数据库集群必须独占两台物理服务器，固定成本会按集群重复。此时不是总数据库 vCPU 达到 34 就能回本，而是单个集群或可安全合并的资源池达到这个规模。Pigsty、KVM 或容器能够减少物理碎片，但不能凭空消除主备副本。

### 6.7 RDS 的本质结论

RDS 的物料拐点很早，因为托管产品价格同时叠加：

- 两节点计算原子。
- 多副本存储原子。
- 备份与快照原子。
- 控制面、故障转移与管理溢价。

用户明确要求不计人力，所以本报告不能用“省 DBA”替 RDS 辩护，也不能用“自建需要 DBA”放大自建成本。纯物料视角下，稳定的中型 PostgreSQL 很快进入自建优势区；是否采用 RDS 最终要由管理能力、风险与弹性价值补足价差。

## 7. 自建 S3/OSS 的规模成本

### 7.1 S3 不是一堆硬盘

对象存储成本至少包含：

`LogicalData x ECOverhead x FreeSpaceReserve x SiteCopies + SpareInventory + Network`

MinIO 的 16 盘 EC:4 示例给出 75% 存储效率；更高 parity 会牺牲更多容量。[MinIO Erasure Coding](https://docs.min.io/aistor/operations/core-concepts/erasure-coding/) 当前 AIStor 文档把生产部署定义为至少 8 个同构 host，并建议跨 rack 或 availability zone 分散故障域。[AIStor Core Concepts](https://docs.min.io/aistor/operations/core-concepts/)

基准使用：

- 75% EC 效率。
- 80% 最大安全填充率。
- 5% 备盘库存。
- 5% 每月数据变更率。
- 每个远程副本站点按 100 TB/月配置一个 1 Gbps 实用端口。

### 7.2 五种拓扑

| 拓扑 | 最小节点 | 最小站点/机柜 | 能回答什么 |
|---|---:|---:|---|
| 4-node lower bound | 4 | 单站点 | 历史 MinIO/容量下界，不是当前 AIStor 完整基线 |
| 8-node single | 8 | 单站点 | 当前生产 host 下界，抗节点/盘故障 |
| 8-node dual | 16 | 两站点 | 异地完整副本，加入复制线路 |
| 8-node three | 24 | 三站点 | 保守地接近多故障域服务 |
| Vault20 | 20 | 20 机柜 | Backblaze 17+3、跨机柜故障域参照 |

Backblaze 把一个文件切成 17 个数据片与 3 个 parity，分布到 20 个 Storage Pod；每个 Pod 是 4U 60 盘服务器。[Backblaze Storage Pod](https://www.backblaze.com/cloud-storage/resources/storage-pod) Backblaze 的不同材料对持久性写过 7 个 9 与 11 个 9 两种表述，因此本报告只把它当架构参照，不声称与 S3 SLA 精确等价。

- MinIO/对象网关负载均衡器、商业支持、证书与控制面硬件没有单列，计入后自建成本上升。
- 两者在工作簿中都可作为附加项输入。

因此报告不把 199 TB 写成普适真理，而把它写成当前物料基准下的容量交点。

- AWS S3 约 150 万美元/年，并且已经签了四年合同。
- 约 6 PB primary data 需要迁移。
- 两个数据中心合计 18 PB Pure Storage，全量异地复制。

- 40 Gbps 迁移线路预计需要约三周。

### 9.3 案例能证明什么，不能证明什么

DHH 能证明：

- 稳定中型 SaaS 可以在不增加运维团队的情况下完成硬件自有化。
- 真实云账单、真实服务器采购与真实机柜报价能产生数百万美元级差额。
- S3 长期合同仍可能比两地企业全闪存储贵约三倍。

DHH 不能证明：

- 所有小企业都能复用其既有机柜。
- 所有工作负载都适合固定容量。
- Pure Storage 与 commodity MinIO 成本相同。
- 其美国 Deft 报价可直接套用中国 IDC。

## 10. 规模经济的标准规律

### 10.1 第一规律：装箱率先于采购折扣

一台服务器从 10% 使用率提升到 70%，单位硬件成本下降 7 倍；批量采购从零折扣到 15%，只下降 15%。先解决容量利用率，再谈商务折扣。

### 10.2 第二规律：最小可靠拓扑决定启动成本

| 服务 | 最小物料台阶 |
|---|---|
| 单机 EC2 类资源 | 1 台服务器 |
| N+1 计算池 | 至少 3 台服务器 |
| RDS 高可用 | 至少 2 台数据库节点 |
| 当前 AIStor 生产基线 | 至少 8 个 host |
| 双站点对象存储 | 至少 16 个 host |
| Backblaze Vault | 20 个 Pod / 20 个机柜故障域 |

### 10.3 第三规律：机柜后曲线快速变平

专业 IDC 已经替用户聚合了土地、电力、UPS、制冷、消防和物理安全。用户从 1U 升到整柜能获得一次批发折扣，从整柜到几十柜还能降低网络与备件分摊；但不会再次获得云厂商从小机房到 hyperscale 的全部 5-7 倍历史红利。

### 10.4 第四规律：状态越重，自建拐点越早

纯计算只租 CPU/内存；RDS 还租两份计算与多份状态；S3 主要租多份廉价容量。资源溢价与状态密度共同决定：

- RDS 因管理加价高，较早进入自建区。
- EC2 居中，长期深折扣可接近硬件成本。
- S3 容量单价本来就低，必须先摊薄可靠性拓扑。

### 10.5 第五规律：云的价值是风险转移

云把以下风险从客户转到供应商：

- 需求预测错误。
- 硬件交货期。
- 小规模故障备件。
- 短期活动峰值。
- 业务失败后的资产闲置。

自建便宜并不等于这些风险没有价值；它只说明稳定负载不应无限期按峰值保险费率付费。

## 11. 敏感性与不确定性

### 11.1 EC2 一阶敏感性

| 变化 | AWS 3年 RI 稳定交点 | 阿里 5年期限稳定交点 |
|---|---:|---:|
| 基准 | 36 vCPU | 2,972 vCPU |
| 利用率 50% | 106 vCPU | 200,000 内未稳定交叉 |
| 利用率 85% | 36 vCPU | 984 vCPU |
| 硬件价 -25% | 29 vCPU | 724 vCPU |
| 硬件价 +25% | 43 vCPU | 12,634 vCPU |
| 3 年折旧 | 162 vCPU | 200,000 内未稳定交叉 |
| 7 年折旧 | 28 vCPU | 701 vCPU |
| 高机房价 | 36 vCPU | 5,387 vCPU |

利用率与硬件寿命是决定性变量。与高价 AWS 按量相比，任何合理情景都很快交叉；与阿里五年价相比，结果可以从数百 vCPU 到完全不交叉。

### 11.2 RDS 一阶敏感性

| 变化 | AWS 1年 RI | 阿里 3年 SP |
|---|---:|---:|
| 基准 | 11 vCPU | 34 vCPU |
| 利用率 50% | 11 vCPU | 51 vCPU |
| 硬件价 -25% | 9 vCPU | 28 vCPU |
| 硬件价 +25% | 13 vCPU | 40 vCPU |
| 3 年折旧 | 16 vCPU | 75 vCPU |
| 7 年折旧 | 9 vCPU | 27 vCPU |

RDS 结论比 EC2 稳健。即使硬件贵 25% 或只用三年，交点仍在几十业务 vCPU，而不是几千。

### 11.3 S3 一阶敏感性，对照阿里一年资源包

| 变化 | 单站点 8节点 | 双站点 8+8 | 三站点 8x3 稳定交点 |
|---|---:|---:|---:|
| 基准 | 199 TB | 536 TB | 1,223 TB |
| 硬件价 -25% | 169 TB | 476 TB | 1,047 TB |
| 硬件价 +25% | 229 TB | 597 TB | 1,399 TB |
| 安全填充 60% | 199 TB | 536 TB | 2,363 TB |
| 月变更率 1% | 199 TB | 536 TB | 1,223 TB |
| 月变更率 20% | 199 TB | 1,047 TB | 7,665 TB |
| 高机房价 | 224 TB | 587 TB | 1,300 TB |

单站点容量成本对变更率不敏感；多站点对象存储对写入 churn 极度敏感。高频改写数据可能更适合块存储、数据库或共享文件系统，而不是把所有副本都按对象跨站点复制。

### 11.4 价格与税口径

- AWS 美元价格通常不含当地销售税，本报告直接按 6.7817 换算。
- 阿里中国站公开价与硬件零售报价通常含增值税，但企业抵扣能力不同。
- IDC 招标价有的含电、有的按 kW、有的将互联网线路分开。
- 商务折扣、Credits 与迁移补贴没有统一公开率。

因此模型输出应理解为可审计的情景估算，不是供应商正式报价。

## 12. 决策矩阵

### 12.1 EC2/ECS

| 条件 | 倾向云 | 倾向自建 |
|---|---|---|
| 负载持续时间 | 少于 12-18 个月 | 3-7 年稳定 |
| 稳定 x86 规模 | 少于 16-24 vCPU | 超过 64-128 vCPU |
| 波动峰谷 | 峰值/均值很高 | 平稳或可排队 |
| 地域 | 全球多地少量节点 | 少数固定 IDC |
| 采购方式 | 按量/Spot | 能接受资产与交货期 |
| 对手价格 | 深度 Spot/补贴实例 | 正常按量或短承诺 |

### 12.2 RDS PostgreSQL

| 条件 | 倾向 RDS | 倾向自建 RDS |
|---|---|---|
| 单集群规模 | 1-8 vCPU | 16-64+ vCPU |
| 生命周期 | 临时、PoC、未知 | 稳定生产 |
| 存储 | 很小、增长未知 | 中大容量 NVMe |
| DBA 能力 | 不具备基础能力 | 有自动化平台或成熟 PostgreSQL 能力 |
| 扩展/权限 | 接受产品边界 | 需要扩展、超级用户和底层控制 |
| 风险购买 | 愿意为托管付 2-10 倍 | 愿意承担硬件和恢复责任 |

### 12.3 S3/OSS

| 条件 | 倾向云对象存储 | 倾向自建对象存储 |
|---|---|---|
| 数据规模 | 少于 100-200 TB | 单站 0.2 PB+，双站 0.5 PB+ |
| 故障域 | 需要开箱即用 3 AZ | 已有多机柜/多 IDC |
| 数据变更 | 高频改写且跨站复制 | 写少读多、可批量同步 |
| 出流 | 很小或高度不确定 | 20-25 TB/月以上稳定出流 |
| 全球分发 | 原生全球访问 | 源站自建 + CDN |
| 起步资本 | 希望为零 | 可采购最小 8 节点池 |

## 13. 实操采购与复算流程

### 13.1 先填业务需求，不先填服务器数量

至少填写：

1. 稳定业务 vCPU、内存与本地盘需求。
2. 峰值/均值、日内波动与季节波动。
3. PostgreSQL primary vCPU、逻辑容量、写入量、备份保留。
4. 对象存储逻辑容量、对象数、PUT/GET、月新增和改写比例。
5. 月公网出流、跨站点复制量。
6. 需要几个站点、几个机柜故障域、RPO/RTO。

### 13.2 再获取三类正式报价

- 服务器/存储节点：同一配置的 1 台、10 台、100 台报价与 3/5 年保修。
- IDC：按 U、5 kW 整柜、10+ 柜专区三档，明确电力、PUE、带宽、IP 与 remote hands。
- 云：按量、1/3 年承诺、企业协议、Credits、支持费与含税账单。

### 13.3 用账单而不是折扣话术

云供应商说“七折”，必须追问：

- 相对目录价、官网折扣价还是按量价？
- 只折计算，还是存储、IOPS、请求、流量都折？
- Credits 是否一次性？
- 未用承诺是否作废？
- 税和 Support 是否另计？

硬件供应商说“便宜”，必须追问：

- CPU 是物理核还是线程？
- 内存、NVMe、网卡、电源和导轨是否完整？
- 保修是 3 年还是 5 年？
- 硬盘是否企业级、是否含托架？
- 交货期、备件和固件支持是什么？

### 13.4 用配套工作簿求自己的交点

工作簿将以下全部设计为可编辑输入：

- 硬件采购价、寿命、资金成本和体量折扣。
- CPU/内存/盘容量、功率、U 数与目标利用率。
- 机柜、kW、交换机、基础线路和高低报价。
- RDS 节点数、存储配比和备份成本。
- 对象存储节点类型、EC、填充率、站点数和 churn。
- AWS/阿里云按量与承诺单位价。

任何真实采购前，应该把正式报价替换公开锚点，再读取交点。

## 14. 局限与保守边界

### 14.1 自建可能被低估的部分

- 商业对象存储软件授权和高级支持。
- 独立负载均衡器、KMS/HSM、审计与合规硬件。
- 多站点专线的建设费与跨城双路由。
- 备份保留超过一份全量。
- 硬件报废、迁移和安全擦除。
- 小规模用户无法获得公开示例价格。

### 14.2 云可能被低估的部分

- S3/OSS 请求、检索、小对象、最短存储期。
- NAT、负载均衡、IPv4、跨 AZ 与跨 Region 流量。
- RDS Proxy、Performance Insights、审计、超额备份和 Extended Support。
- AWS 税、Enterprise Support 和中国站特殊溢价。
- 承诺闲置、规格锁定和 Credits 到期。

### 14.3 服务能力不能由物料价格推出

本报告只回答物料经济性，不能直接证明：

- 自建服务会达到云 SLA。
- 云服务一定比自建可靠。
- MinIO/Ceph/Pigsty 与 S3/RDS 功能逐项相同。
- 某个公司具备执行迁移的组织能力。

经济拐点是进入工程评估的门槛，不是自动迁移指令。

## 15. 最终结论

### 15.1 EC2

在企业级服务器和中国 IDC 公开报价下，只要稳定负载能够占用一台现代服务器的很小一部分，自建就可能低于 AWS/阿里按量；对 1-3 年承诺，几十到数百 vCPU 后优势稳定。阿里五年深折扣是少数能接近硬件物料成本的云方案，其胜负高度依赖利用率、折旧寿命和扩容阶梯。

### 15.2 RDS

RDS 的纯物料拐点最早。64 GiB/业务 vCPU 基准下，AWS/阿里正常价约在 8-11 业务 vCPU 交叉，即使阿里 3 年全预付也约在 34 vCPU。稳定中大型 PostgreSQL 若长期运行，RDS 价差必须由托管价值、风险转移和组织能力来证明，而不能再用硬件成本解释。

### 15.3 S3

对象存储不是到 10 TB 就应该自建，也不是到 25 PB 才能自建。当前物料基准给出的实际区间是：

- 约 0.1-0.2 PB：单站点容量开始有经济性。
- 约 0.3-0.6 PB：双站点对象存储开始跨过正常云价。
- 约 0.6-1.3 PB：三站点或 20 机柜故障域架构进入优势区。
- 数 PB：单位容量进入云价的约三分之一到十分之一，DHH 的 Pure Storage 实账提供了独立验证。

### 15.4 终极判断

> 云最擅长承接未知、短暂、波动和分散的需求；自建最擅长承接稳定、持续、状态密集和带宽密集的需求。规模不是服务器数量，而是可持续填满最小可靠拓扑的业务负载。

当真实负载越过本报告给出的区间后，继续不做正式采购比较，才是最大的 FinOps 风险。
